## `const` və `let` — `var` heç vaxt istifadə etməyin

Hər test faylında iki dəyişən açar sözü görəcəksiniz: `const` və `let`.

```javascript
const baseURL = 'http://localhost:3000';  // yenidən mənimsədilməyəcək
let retryCount = 0;                        // sonra dəyəri dəyişəcək
```

**Qayda:** standart olaraq `const` istifadə edin. Dəyişənə yeni dəyər mənimsətməli olduqda `let`-ə keçin.

```javascript
// ✅ Düzgün
const TIMEOUT = 30000;
let attempts = 0;
attempts = attempts + 1;  // yaxşıdır — let yenidən mənimsətməyə icazə verir

// ❌ Xəta verir
const MAX = 5;
MAX = 10;  // TypeError: Assignment to constant variable
```

Vacib bir məqam: `const` dəyişməzlik demək deyil. Obyekt xüsusiyyətlərini dəyişdirmək mümkündür:

```javascript
const config = { retries: 1 };
config.retries = 2;       // ✅ bu icazəlidir
config = { retries: 3 };  // ❌ bu icazəsizdir — referansı yenidən mənimsədə bilməzsiniz
```

`var` haqqında: mövcuddur, amma gözlənilməz scope xətaları yaradır. Bütün müasir linter-lər bunu işarələyir. Playwright layihəsində heç vaxt `var`-a ehtiyac olmayacaq.

## String, rəqəm və boolean

Bu üç primitiv tip test fayllarında istifadə edəcəyiniz şeylərin böyük hissəsini əhatə edir.

### String-lər

```javascript
const url = 'http://localhost:3000/login';
const selector = '#email-input';

// Template literal (backtick) — dəyər yerləşdirəndə bunları istifadə edin
const message = `Keçildi: ${url}`;
const fullSelector = `[data-testid="${selector}"]`;
```

Template literal-lar (backtick-li string-lər) Playwright-də çox istifadə olunur — konfiqurasiya fayllarında, page object-lərdə və iddia ifadələrində.

### Rəqəmlər

```javascript
const timeout = 5000;   // millisaniyə
const retries = 3;
const price = 19.99;
```

Tip çevrilərinə diqqət edin:

```javascript
'5' - 3  // → 2   (JS string-i rəqəmə çevirir)
'5' + 3  // → '53' (JS 3-ü string-ə çevirir — tələ!)
```

Praktikada açıq çevirmədən istifadə edin: `Number('5')` və ya `parseInt('5', 10)`.

### Boolean

```javascript
const isLoggedIn = true;
const hasErrors = false;

// Həmişə === (ciddi bərabərlik), heç vaxt ==
'5' === 5   // → false (fərqli tiplər)
'5' == 5    // → true  (tip çevrilməsi — bundan qaçın)
```

Playwright-də boolean-lar iddia ifadələrində (`expect(isVisible).toBe(true)`) və konfiqurasiyada (`headless: true`) görünür.

## Array-lər və obyektlər

### Array-lər

```javascript
const browsers = ['chromium', 'firefox', 'webkit'];
const prices = [9.99, 14.99, 29.99];

// Ümumi əməliyyatlar
browsers.length;              // 3
browsers[0];                  // 'chromium'
browsers.push('electron');    // sona əlavə edir
browsers.filter(b => b !== 'webkit');  // 'webkit' olmadan yeni array qaytarır
browsers.map(b => b.toUpperCase());    // ['CHROMIUM', 'FIREFOX', 'WEBKIT']
```

### Obyektlər

```javascript
const user = {
  email: 'customer@test.io',
  password: 'customer123',
  role: 'admin',
};

// Xüsusiyyətlərə giriş
user.email;           // 'customer@test.io'
user['role'];         // 'admin' — dinamik açarlar üçün mötərizə notasiyası
```

### Destructuring

Destructuring, obyekt və array-lərdən dəyərləri təmiz şəkildə çıxarmağa imkan verir:

```javascript
const { email, password } = user;
// eyni məna daşıyır: const email = user.email; const password = user.password;

const [first, second] = browsers;
// eyni məna daşıyır: const first = browsers[0]; const second = browsers[1];
```

Playwright-də bunu daim görəcəksiniz — məsələn, freymvorkdan `test` və `expect`-i çıxararkən:

```javascript
const { test, expect } = require('@playwright/test');
```

### Spread operatoru

Spread operatoru (`...`) obyekt və array-ləri kopyalayır və birləşdirir:

```javascript
const defaultOptions = { headless: true, slowMo: 0 };
const debugOptions = { ...defaultOptions, headless: false, slowMo: 500 };
// → { headless: false, slowMo: 500 }
```

Test konfiqurasiyalarını birləşdirmək və dəyişdirilmiş test data obyektləri yaratmaq üçün geniş istifadə olunur.

## Funksiyalar və arrow funksiyalar

### Adi funksiyalar

```javascript
function formatPrice(price) {
  return `$${price.toFixed(2)}`;
}
```

### Arrow funksiyalar

Arrow funksiyalar daha qısa, müasir sintaksisdır — Playwright-də hər yerdə görünür:

```javascript
const formatPrice = (price) => `$${price.toFixed(2)}`;

// Çox sətirli arrow funksiya { } və açıq return tələb edir
const generateUser = (role) => {
  const timestamp = Date.now();
  return { email: `${role}_${timestamp}@test.io`, role };
};
```

Hər Playwright testi arrow funksiyadan istifadə edir:

```javascript
test('istifadəçi daxil ola bilər', async ({ page }) => {
  await page.goto('/login');
  // ...
});
```

**Nəyi nə vaxt istifadə etməli:**

- Arrow funksiyalar: callback-lər, test gövdələri, qısa köməkçi funksiyalar
- Adi `function`: class metodları (məsələn, `this` istifadə edən Page Object metodları)

### Gizli return tələsi

Tək ifadəli arrow funksiyalar dəyəri gizlin qaytarır — `return` açar sözü lazım deyil:

```javascript
const double = x => x * 2;      // gizlin return — x * 2 qaytarır
const triple = x => { x * 3 };  // ❌ return yoxdur — undefined qaytarır
const triple = x => { return x * 3 };  // ✅ açıq return
```

## Import və export (CommonJS modulları)

Playwright standart olaraq **CommonJS** modullarından istifadə edir. Bu, `require()` və `module.exports` deməkdir.

### Import etmək

```javascript
// Moduldan hər şeyi import et
const { test, expect } = require('@playwright/test');

// Öz faylınızı import edin
const LoginPage = require('./pages/LoginPage');

// Bir neçə şeyi import edin
const { chromium, firefox } = require('@playwright/test');
```

### Export etmək

```javascript
// LoginPage.js — başqaları import edə bilsin deyə class-ı export edirik
class LoginPage {
  constructor(page) {
    this.page = page;
  }
}

module.exports = LoginPage;
```

`module.exports`-u unutsanız, import `{}` qaytaracaq və `TypeError: LoginPage is not a constructor` kimi xətalar görəcəksiniz.

### ES modulları (`import`/`export`)

Bəzi kod bazalarında ES modul sintaksisi də görə bilərsiniz:

```javascript
import { test, expect } from '@playwright/test';
export default LoginPage;
```

`package.json`-a `"type": "module"` əlavə etsəniz, bu Playwright-də işləyir. Kurs maksimum uyğunluq üçün CommonJS-dən istifadə edir, amma hər iki üsul işləyir.

## Promise-lər və async/await

Bu bölmə flaky testlərdən qaçmaq üçün ən vacibdir. **`await` unutmaq test uğursuzluqlarının 1 nömrəli səbəbidir.**

### Promise nədir?

Promise hələ mövcud olmayan bir dəyəri təmsil edir — asinxron əməliyyatın nəticəsidir. Playwright demək olar ki, hər əməliyyatdan Promise qaytarır:

```javascript
// page.goto() Promise qaytarır
const promise = page.goto('/login');  // naviqasiyanı başladır amma gözləmir
```

### `await` dayanır və gözləyir

```javascript
async function login() {
  await page.goto('/login');         // naviqasiyanın tamamlanmasını gözləyir
  await page.fill('#email', '...');  // doldurmağın tamamlanmasını gözləyir
  await page.click('button');        // klikləmənin tamamlanmasını gözləyir
}
```

`await` olmadan test əməliyyat bitmədən növbəti sətirə keçir:

```javascript
// ❌ await yoxdur — test dərhal davam edir
page.goto('/login');
page.fill('#email', 'user@test.io');  // səhifə hələ yüklənməyib ola bilər!
expect(page).toHaveURL('/dashboard');  // login olmadan işləyir!
```

### `async` açar sözü

`await` istifadə edən hər funksiya `async` ilə elan edilməlidir:

```javascript
// ✅ Düzgün
async function runTest() {
  await page.goto('/');
}

// Arrow funksiya kimi də işləyir
const runTest = async () => {
  await page.goto('/');
};
```

`async` funksiya həmişə Promise qaytarır. Əgər async funksiyadan `'salam'` qaytarsanız, çağıran tərəf `Promise<'salam'>` alır — onlar da `await` etməlidir.

### `Promise.all` — paralel əməliyyatlar

Eyni anda bir neçə şeyi gözləmək lazım olduqda:

```javascript
// Naviqasiya VƏ başqa bir şeyi eyni anda gözləyin
const [response] = await Promise.all([
  page.waitForResponse('/api/login'),
  page.click('button[type="submit"]'),
]);
```

Bu, klik etdikdə şəbəkə sorğusunu gözləmək lazım olan naviqasiya şablonları üçün istifadə olunur.

## TypeScript əsasları

Playwright-in TypeScript üçün tam dəstəyi var. `.ts` faylları əlavə konfiqurasiya olmadan işləyir.

### Niyə TypeScript?

TypeScript kodu işlətməzdən əvvəl xətaları aşkar edən **tip annotasiyaları** əlavə edir:

```typescript
// JavaScript — xəta yalnız işləmə zamanı baş verir
function formatPrice(price) {
  return `$${price.toFixed(2)}`;
}
formatPrice('rəqəm-deyil');  // işləmə zamanı çöküş

// TypeScript — xəta dərhal redaktorda görünür
function formatPrice(price: number): string {
  return `$${price.toFixed(2)}`;
}
formatPrice('rəqəm-deyil');  // ❌ TypeScript xətası
```

### Əsas tip annotasiyaları

```typescript
// Primitivlər
const url: string = 'http://localhost:3000';
const timeout: number = 5000;
const headless: boolean = true;

// Array-lər
const browsers: string[] = ['chromium', 'firefox', 'webkit'];

// Funksiyalar
function getUser(role: string): { email: string; role: string } {
  return { email: `${role}@test.io`, role };
}
```

### Interface-lər

Interface-lər obyektin formasını təsvir edir. Test data üçün istifadə edin:

```typescript
interface User {
  email: string;
  password: string;
  role: 'admin' | 'customer';  // union type — yalnız bu iki dəyər
}

interface Product {
  name: string;
  price: number;
  category: string;
}

const user: User = {
  email: 'customer@test.io',
  password: 'customer123',
  role: 'customer',
};
```

### İstəyə bağlı xüsusiyyətlər

Xüsusiyyəti istəyə bağlı etmək üçün `?` əlavə edin:

```typescript
interface ShippingDetails {
  name: string;
  address: string;
  city: string;
  zip: string;
  country?: string;  // istəyə bağlı — undefined ola bilər
}
```

### JSDoc — `.ts` faylları olmadan TypeScript faydaları

Sadə `.js` fayllarında tip yoxlaması istəyirsinizsə, JSDoc annotasiyalarından istifadə edin:

```javascript
/**
 * @param {number} price
 * @returns {string}
 */
const formatPrice = (price) => `$${price.toFixed(2)}`;

/**
 * @param {import('@playwright/test').Page} page
 */
constructor(page) {
  this.page = page;
}
```

VS Code bu annotasiyaları oxuyur və sizə avtomatik tamamlama və tip xətaları göstərir — TypeScript kimi, amma heç bir build addımı olmadan.

## Xətaları və stack trace-ləri oxumaq

Test uğursuz olduqda, xəta mesajı nə baş verdiyini dəqiq deyir — əgər oxumağı bilsəniz.

### Stack trace-in anatomiyası

```
TypeError: Cannot read properties of undefined (reading 'click')
    at LoginPage.login (/project/tests/pages/LoginPage.js:18:22)
    at Context.<anonymous> (/project/tests/login.spec.js:15:12)
    at Test.runner (/project/node_modules/@playwright/test/lib/test.js:142:5)

  Failure in test 'admin can login to dashboard'
  tests/login.spec.js:10:3
```

Oxuma qaydası:

1. **Birinci sətir** — xəta tipi və mesajı: `TypeError: Cannot read properties of undefined`. Bir şey `undefined`-dir və siz onun üzərində `.click()` çağırmağa cəhd etdiniz.
2. **İkinci sətir** — xətanın faktiki baş verdiyi yer: `LoginPage.js:18:22` (fayl, sətir, sütun).
3. **Üçüncü sətir** — uğursuz kodu çağıran yer: `login.spec.js:15`.
4. **Aşağı hissə** — test adınız və testin başladığı sətir.

**`node_modules` sətirlərinə məhəl qoymayın** — bunlar Playwright-in daxili işləridir. Öz fayllarınıza diqqət edin.

### Ümumi xətalar və mənası

| Xəta | Məna | Həll |
|------|------|------|
| `Cannot read properties of null (reading 'click')` | Selector heç nə tapmadı — element `null`-dur | Selector-u yoxlayın, elementin mövcud olduğunu yoxlayın |
| `Cannot read properties of undefined` | Dəyişən mənimsədilməyib | Import-ları, dəyişən scope-unu yoxlayın |
| `ReferenceError: X is not defined` | Dəyişən scope-da elan edilməyib | Yazılışı, elan yerini yoxlayın |
| `TypeError: X is not a function` | Yanlış şey import edilib ya `module.exports` unudulub | `console.log(typeof X)` yoxlayın |
| Çıxış sırası yanlışdır | `await` yoxdur | Asinxron çağırışlardan əvvəl `await` əlavə edin |

## Mühit dəyişənləri

URL-ləri, parolları və ya tokenləri test fayllarına heç vaxt birbaşa yazmayın. Bunun əvəzinə mühit dəyişənlərindən istifadə edin.

### `process.env`-dən oxumaq

```javascript
const baseURL = process.env.BASE_URL;
const adminEmail = process.env.ADMIN_EMAIL;
```

### Standart dəyərlər və məcburi dəyişənlər

```javascript
function getConfig() {
  const baseUrl = process.env.BASE_URL || 'http://localhost:3000';  // standart dəyər

  const adminEmail = process.env.ADMIN_EMAIL;
  if (!adminEmail) {
    throw new Error('ADMIN_EMAIL mühit dəyişəni tələb olunur');
  }

  const isCI = process.env.CI === 'true';  // string-i boolean-a çevir

  return { baseUrl, adminEmail, isCI };
}
```

### `.env` faylları

Layihə kökündə `.env` faylı yaradın:

```
BASE_URL=http://localhost:3000
ADMIN_EMAIL=admin@test.io
ADMIN_PASSWORD=admin123
CI=false
```

Sonra konfiqurasiyada `dotenv` ilə yükləyin:

```javascript
require('dotenv').config();
// İndi process.env.BASE_URL, process.env.ADMIN_EMAIL və s. mövcuddur
```

**`.env`-i həmişə `.gitignore`-a əlavə edin** — sirrləri heç vaxt version control-a göndərməyin.

Playwright konfiqurasiyasında bu şablonu görəcəksiniz:

```javascript
// playwright.config.js
module.exports = {
  use: {
    baseURL: process.env.BASE_URL || 'http://localhost:3000',
  },
  forbidOnly: !!process.env.CI,  // !! string-i boolean-a çevirir
};
```

### Tapşırıq 4: Xətalı asinxron kodu düzəldin

Aşağıdakı kodda **4 əksik `await` açar sözü** var. Onları tapın və düzəldin.

```javascript
const fakePage = {
  goto: (url) => Promise.resolve(`Keçildi: ${url}`),
  fill: (selector, value) => Promise.resolve(`${selector} dolduruldu: ${value}`),
  click: (selector) => Promise.resolve(`Klik edildi: ${selector}`),
  waitForSelector: (selector) => Promise.resolve(`Gözlənildi: ${selector}`),
  screenshot: () => Promise.resolve('Ekran görüntüsü alındı'),
};

async function runTest() {
  console.log('Test başlayır...');

  fakePage.goto('/auth/login');           // ❌ await yoxdur
  console.log('Login səhifəsinə keçildi');

  fakePage.waitForSelector('#email');     // ❌ await yoxdur
  fakePage.fill('#email', 'customer@test.io');  // ❌ await yoxdur
  fakePage.fill('#password', 'customer123');
  fakePage.click('button[type="submit"]');

  console.log('Login formu göndərildi');
  fakePage.screenshot();                  // ❌ await yoxdur
  console.log('Ekran görüntüsü alındı');

  console.log('Test tamamlandı!');
}

runTest();
```

Əvvəlcə xətalı versiyanu işlədin — çıxış sırasının yanlış olduğunu görəcəksiniz. Sonra `await` əlavə edib yenidən işlədin.

## Əsas nəticələr

Yapışqan kağıza yazacağınız dörd qayda:

1. **Standart olaraq `const`, yenidən mənimsətmək üçün `let`, heç vaxt `var`**
2. **Hər Playwright əməliyyatını `await` edin** — `await` unudulması = flaky test
3. **Stack trace-ləri aşağıdan yuxarı oxuyun** — faylınız aşağıdadır, xəta yuxarıdadır
4. **Sirrləri heç vaxt kodda yazmayın** — `process.env` və `.env` fayllarından istifadə edin
