So far your programs have only talked. Now let's teach them to **listen**: `input()` gets information from the user.

:::note[How does input() work in our playground?]
On a normal computer, `input()` pauses the program and waits for the user to type. In our code playground, you write the answers **in advance** in the "Inputs" box — one answer per line. Each time the program calls `input()`, it takes the answers from there in order.
:::

## First conversation

In the example below, `Aysel` is already written in the "Inputs" box. Open the box and take a look, then run it:

<PyRunner
	id="ex-input"
	starterCode={`name = input("What's your name? ")\nprint(f"Hello, {name}! Nice to meet you.")`}
	inputs={'Aysel'}
	height="5rem"
/>

`input("What's your name? ")` — shows the question, takes the answer, and puts it in the `name` box. Change the name in the Inputs box and run it again!

## Heads up: input() always returns text

Here's the trap. Even if the user types `12`, `input()` returns it as **text** — `"12"`. You can't do math with text:

<PyRunner
	id="ex-tele"
	starterCode={`age = input("How old are you? ")\nprint(age + 1)`}
	inputs={'12'}
	height="5rem"
/>

Run it — you'll see an error: Python says it can't add a number to text. The fix: use `int()` to turn the text into a **whole number**:

<PyRunner
	id="ex-int"
	starterCode={`age = int(input("How old are you? "))\nprint(f"Next year you'll be {age + 1}!")`}
	inputs={'12'}
	height="5rem"
/>

The rule is simple: **if you need to do math with a number — `int(input(...))`.**
