Each failure, its status

The 4xx family

400
Bad Request
missing / invalid input
401
Unauthorized
bad credentials
404
Not Found
resource doesn't exist
409
Conflict
duplicate / clashes
🔒Security touch: wrong password and unknown email both return the same 401 — so the API never leaks which emails exist.

One test, a table of bad inputs
@pytest.mark.parametrize(
"payload, expected",
[
(valid, 200), # control
(bad_pw, 401),
(missing, 400),
])
pytest -v
test_login[valid] PASSED
test_login[bad-password] PASSED
test_login[missing] PASSED
Keep one valid control row — a failing negative row is then about the input, not a broken endpoint.

When the API fails wrong

Negative testing finds real bugs

POST duplicate name → 500 💥
→
encode it: @xfail(strict=True) asserting 409
→
XFAIL today · XPASS+fail when fixed
🏷️A strict=True xfail documents a known bug, keeps the suite green today, and fails loudly the moment it's fixed — so the stale marker can't linger.
