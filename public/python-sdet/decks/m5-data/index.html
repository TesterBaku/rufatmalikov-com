Arrange via the API, not the UI

Need a logged-in user with an order? Don't click through signup → login → checkout. POST the data straight in — one fast, reliable call — then test the thing you actually care about.

⚡API setup is faster and far less flaky than driving the UI to build state.
# arrange: one API call, not 6 UI clicks
order = api.post(
f"{base_url}/api/orders",
json={"email": user, "items": […]},
).json()
# act + assert on what matters
assert order["total"] == pytest.approx(59.98)

Set up before yield, clean up after
@pytest.fixture
def temp_product(api, base_url):
# setup
p = api.post(…/products).json()
yield p # hand it to the test
# teardown — always runs
api.delete(f"…/products/{p['id']}")
♻️Code before yield is setup; code after is teardown — and it runs even if the test fails.
🏭Need several? A factory fixture returns a function the test calls N times — each with a unique name, and reset_db reseeds it all away after.
